## 0. Executive Summary — 제품이 반드시 해결해야 할 문제

차여기는 *주차한 위치를 기록한 다음 사진첩을 다시 뒤져야 하는 번거로움*을 줄이는 데서 시작하지만, 최종적으로 해결해야 할 문제는 기록 그 자체가 아니다. 사용자는 낯선 대형 건물의 복잡한 주차장에 차를 세운 뒤 **주차 위치를 기억하지 않아도 안전하고 빠르게 차량으로 복귀하고 싶다**. 기존 카메라·메모·지도 앱으로도 기록은 가능하므로, 차여기가 카메라보다 먼저 선택되지 않으면 별도 제품으로 생존하기 어렵다.

**북극성(North Star):** `주차 위치 기록이 필요한 실제 상황에서 차여기를 통해 시작하고, 그 기록을 이용해 차량 복귀를 완료한 세션 수`(Qualifying Assisted Returns, QAR). 사용자 수·다운로드 수·촬영 횟수만으로 제품 성공을 정의하지 않는다.

**핵심 가치 제안**
1. **기록을 잊지 않기:** 주차 관련 상황에서 빠른 실행 경로를 제공하되, OS 자동 감지를 과장하지 않는다.
2. **사진 한 장으로 기록:** 사진 촬영과 영속 저장을 우선 완료하고, 문자 인식은 뒤에서 처리한다.
3. **차로 돌아가는 단서 제공:** 층·구역·기둥·출입구·엘리베이터·원본 사진·시간을 한 화면에 모은다.
4. **증빙과 재사용 가치:** 촬영 사진과 시각을 구분해 보존하고, 동승자 공유·주차 경과 시간·이력 관리를 지원한다.
5. **프라이버시 우선:** 초기에는 계정·서버 없이 기기 내 처리한다. 동기화·시설 데이터 활용은 이용자의 별도 선택과 검토를 거친다.

**제품 논리:** `상황적 신호 → 즉시 실행 → 촬영/저장 → 필요한 단서 추출 → 볼일 → 복귀 → 완료 → 다음 유사 상황에서 자발적 재사용`.

**중요한 반증 가능성:** *“필요할 때는 유용하지만 실행 습관을 만들 만큼 충분히 자주/강하게 필요하지 않을 수 있다.”* 이 경우 독립 B2C 앱을 무리하게 확대하지 않고, OS 공유 기능·시설 QR·B2B 탑재형으로 방향을 전환한다.

### 1.3 제품 의사결정 우선순위
1. **사용자 신뢰 > AI 자동화의 화려함.** 모르면 모른다고 표시한다.
2. **사진 저장 성공 > OCR 성공.** 분석이 실패해도 기록을 잃지 않는다.
3. **실제 복귀 가능성 > 단순 촬영 수.** 사진첩보다 나은지를 현장에서 비교한다.
4. **실제 동의 > 자의적 추적.** 자동 감지·위치·사진 공유 기능은 기능별 최소 권한.
5. **기본 카메라와의 경쟁 > 기능 개수.** 새로운 행동을 강요하기보다 기존 행동을 흡수한다.
6. **사용자 1명에게 확실한 효용 > 전 시설 커버리지.** 지도 데이터가 없어도 이용 가능해야 한다.
7. **수익 검증 전 과잉 구축 금지.** B2B 전용 엔진을 선행 구축하지 않는다.

## 2. 문제 정의 및 관찰해야 할 실제 행동

### 2.1 문제 서술
- 사용자는 쇼핑몰·백화점·대형병원·공항·오피스 등에서 주차 위치 표기(B3, C-27 등)를 기억하기 어렵다.
- 주차 직후에는 목적지가 우선이며, 사진 촬영 자체를 잊거나 “나중에 기억나겠지”라고 판단할 수 있다.
- 기존 사진은 사진첩의 다른 이미지들과 섞여 복귀 순간 다시 찾아야 한다.
- 일부 시설에서는 같은 층·구역을 알아도 서로 다른 동, 엘리베이터, 출입구 때문에 복귀 동선이 꼬인다.
- GPS/지도의 ‘차량 위치’는 지하주차장 층·기둥 번호를 신뢰성 있게 나타내지 못할 수 있다.
- 문제 발생 빈도가 낮으면 전용 앱을 설치/실행하는 행동 비용이 혜택보다 클 수 있다.

### 2.2 세 가지 다른 문제를 분리한다
| 문제 | 사용자 행동 | 해결 수단 | 실패 요인 |
|---|---|---|---|
| 기록 시작 문제 | 주차 후 촬영을 생략하거나 카메라 실행 | 빠른 진입, 상황 신호, OS 공유, 시설 QR | 알림 피로·진입 단계 증가 |
| 정보 기록 문제 | 사진은 찍지만 의미 있는 정보가 흩어짐 | 원본+OCR+선택적 출입구/메모 | 흐린 이미지·표기 형식 다양 |
| 차량 복귀 문제 | 사진첩 탐색, 잘못된 엘리베이터 이용 | 활성 세션 카드, 사진, 복귀 단서, 동승자 공유 | 부정확한 정보·길 안내 과장 |

### 2.3 핵심 Jobs-to-be-Done(JTBD)
- **기능적:** “낯선 주차장에 차를 세웠을 때, 별다른 입력 없이 돌아올 때 필요한 정보를 남기고 싶다.”
- **기능적:** “볼일이 끝났을 때, 사진첩을 찾지 않고 내 차가 있는 층·구역과 출입구를 바로 확인하고 싶다.”
- **감정적:** “차를 어디에 세웠는지 잊을까 불안해하지 않고 본래 용무에 집중하고 싶다.”
- **사회적:** “동승자/가족에게 차 위치를 빠르게 알려주고 싶다.”
- **상황적:** “주차 가능 시간이 제한될 때, 얼마나 지났는지 확인하고 싶다.”

### 2.4 비목표(하지 않을 것)
- 모든 지하주차장의 차량까지 자동으로 정확한 실내 턴바이턴 경로를 제공한다고 약속하지 않는다.
- 주차 공간을 촬영 없이 자동 인지한다고 주장하지 않는다.
- 기록한 시간과 사진을 공식 주차요금 분쟁의 확정 증거로 표기하지 않는다.
- 사용자의 이동 경로를 상시 추적하거나, 사진·방문 이력을 별도 동의 없이 매각·광고 데이터로 사용하지 않는다.
- 주차장 지도·요금·주차 가능 면수를 추정치로 확정 표시하지 않는다.

### 3.1 사용 환경 제약
- 주차장 통신 불량·비행기 모드·낮은 배터리·낮은 조도·흔들린 사진.
- 카메라 접근 권한 거부·모바일 브라우저 파일 선택기 동작 차이.
- 주차 위치 표시가 한글·영문·숫자 혼합(`지하3층`, `B3`, `C동`, `C-27`, `A구역 015`).
- 차량은 여러 동/층에 중복 표기된 숫자를 가질 수 있다.
- 볼일 중 수 시간 경과, 기기 재시작, 앱 종료, 오프라인 복귀.
- 손 한 개 사용·짐·우산·아이 동반 등 빠른 조작이 필요한 상황.

## 4. 시장 대안과 경쟁 가설

### 4.1 사용자의 실제 경쟁 상대
1. **기본 카메라 + 사진첩**: 별도 설치나 학습 비용이 없다. 최고의 비교 기준.
2. **휴대폰 메모/메신저 자기 대화**: 글자 입력 또는 사진 공유.
3. **범용 지도 앱의 주차 위치 표시 기능**: 외부 지도 위치에는 강점, 복잡한 실내 주차면에는 한계 가능.
4. **차량 제조사 앱/커넥티드카**: 차량별 지원 기능·정확도·요건이 다르다.
5. **시설의 차량 찾기 키오스크/주차 관제 앱**: 해당 시설 내 조회는 유리할 수 있으나 시설별 경험이 달라진다.
6. **기존 주차 위치 기록 전용 앱**: 사진·층수·구역 기록 기능만으로는 신규성이 낮다.

### 4.2 차별화 전략
- ‘사진 저장’은 **테이블 스테이크**. **진입 1회 + 복귀 카드 1회**로 필요한 일을 끝내야 한다.
- 기본 카메라보다 이길 가능성이 있는 순간: (a) 촬영 직후 자동 정리, (b) 복귀 때 단번에 찾기, (c) 출입구 단서, (d) 기록 누락 방지.
- 사진첩과 경쟁하지 못하면 기본 카메라의 **공유 확장/가져오기 보조 도구** 또는 **시설 QR 웹서비스**로 전환한다.

### 4.3 실험으로 확인할 경쟁 가설
- H-C1: 복귀 시 사진첩을 찾는 시간보다 차여기 활성 기록 진입이 유의미하게 빠르다.
- H-C2: 초기 원터치 진입을 설정한 사용자는 기본 카메라보다 차여기를 자발적으로 선택한다.
- H-C3: 출입구/엘리베이터 기록은 층/구역만 저장한 방식 대비 복귀 실패를 줄인다.
- H-C4: 자동 알림은 기록 누락을 줄이지만, 과도하면 해제·삭제를 유도한다.

## 5. 제품 목표, KPI, 실험 성공/중단 기준

### 5.1 핵심 목표(Objectives)
- **O1 신뢰성:** 사진 촬영 후 기록 손실 없이 저장된다.
- **O2 행동 전환:** 실제 주차 필요 시 기본 카메라 대신 자발적으로 차여기를 실행한다.
- **O3 복귀 효용:** 기록을 이용하면 사진첩 대비 복귀 관련 탐색 비용이 줄어든다.
- **O4 데이터 가치:** 사진·층·구역·출입구·시간을 사용자가 통제하면서 활용한다.
- **O5 사업 타당성:** 이용 경험만 좋을 뿐 유통/수익이 없는 함정을 조기 발견한다.

### 5.2 정의가 있는 지표
| 이름 | 정확한 정의 | 분석 단위 | 주의 |
|---|---|---|---|
| Eligible Parking Opportunity (EPO) | 인터뷰/현장 조사에서 “기록할 필요를 느꼈거나 실제 기록 행동을 한” 주차 상황 | 주차 상황 | 전체 주차 대비로 확대 해석 금지 |
| Start Rate | 차여기 기록 시작 EPO / 전체 관찰 EPO | 상황 | 알림 강제 클릭 제외 |
| Capture Completion Rate | 정상 저장 세션 / 촬영 시작 세션 | 세션 | 저장 완료는 UI 클릭이 아니라 로컬 커밋 성공 |
| Median Capture Time | 진입 이벤트→로컬 저장 성공까지 중앙값 | 세션 | 기기/경로별 분리 |
| Assisted Return Rate | 차여기 기록을 실제 복귀 때 연 세션 / 유효 기록 세션 | 세션 | 열기만 하고 도움 없었다면 별도 구분 |
| Voluntary Reuse Rate | 두 번째 이후 EPO에서 연구 지시 없이 차여기를 선택한 사용자/상황 비율 | 반복 EPO | 설치 후 보유일이 아닌 재사용 기회 기준 |
| Retrieval Time | 차 위치 정보를 다시 찾기 시작→필요 단서 확인 시점 | 상황 | 실내 보행·차량 도착 시간과 분리 |
| Return Success | 실제 차량 도착 전 오류/우회 여부, 사용자가 유용했다고 응답했는지 | 현장 과업 | GPS 거리만으로 평가 금지 |
| False Prompt Rate | 주차하지 않았는데 발송된 기록 유도 알림 / 평가 가능한 전체 알림 | 알림 | 사용자 표본으로 오탐 판정 |
| OCR Field Precision | 층·구역·번호 각각 정확 추출한 필드 / 모델이 값을 제안한 필드 | 필드 | 전체 평균 하나로 합치지 말 것 |
| OCR Field Recall | 원본에 읽을 수 있는 필드 중 인식한 필드 / 읽을 수 있는 전체 필드 | 필드 | 불명확 사진 제외 기준 정의 |
| Local Save Failure Rate | 저장 트랜잭션 실패 / 저장 시도 | 시도 | 저장 공간 부족 분리 |
| Feature Opt-out Rate | 자동 감지/알림/분석 설정 해제율 | 사용자 | 동의하지 않은 사람은 모수에서 제외 |

### 5.3 사전 등록할 실험 목표(가설값, 업계 기준 아님)
| 검증 항목 | 초기 통과 기준 제안 | 미달 시 조치 |
|---|---|---|
| 사진 촬영→영속 저장 시간 | 중앙값 ≤ 5초 (지원 기기, 정상 조건) | 저장 경로·이미지 처리 축소 |
| 촬영 시작 후 정상 저장 | ≥ 95% | 출시 확대 중단, 저장/복구 개선 |
| 반복 EPO에서 자발적 선택 | ≥ 60% | 실행 방식·제품 형태 재설계 |
| 기존 사진첩 대비 단서 확인 시간 | 중앙값 ≥ 20% 단축 | 복귀 카드 정보 구조 개선 |
| 주차 감지 오탐 | 평가 가능 알림 중 < 10% 목표 | 알림 빈도 감소/기능 중단 |
| OCR 정확성 | 층/구역/번호 각 필드별 목표를 데이터 수집 후 확정 | 신뢰도·수정 UX 강화 |
| 사용자 체감 도움 | 실제 복귀에 도움 됐다는 응답 ≥ 70% | JTBD 재검토 |

표본이 작으므로 위 목표 달성은 **확증이 아니라 다음 실험을 진행할 근거**다. 표본수·신뢰구간·시설/기기 편향을 함께 보고한다.

### 5.4 North Star 정의 주의
QAR 계산을 위해 정확한 **주차 기회 데이터**가 필요한데, 초기 무계정·로컬 웹은 이를 서버에서 완전 측정할 수 없다. 초기에는 참가자 동의 기반 현장 관찰/설문·로컬 측정치 내보내기로 추정한다. 향후 옵트인 익명 분석 파이프라인을 별도 설계한다.

### 6.1 MVP 코드와 PRD 간 주요 간극(Gap)
- 현재는 새 세션 생성 직전 `closeExisting()`으로 기존 활성 세션을 **자동 완료**한다. 목표 제품은 사용자에게 **이전 기록 완료/교체/취소를 명시적으로 선택**하게 해야 한다.
- 현재 OCR은 `eng` 모델을 CDN에서 로딩하며, **한글 표기를 읽는다고 보장할 수 없다**. 향후 한국어 OCR 또는 규칙 보완 필요.
- 현재 `ocr.confidence`가 있어도 **층/구역/기둥 각 필드의 개별 신뢰도**는 없다. 제안과 확정값 분리 필요.
- 현재 보관된 원본 사진은 기본적으로 무손실 Blob이며 저장 용량 압박 위험이 있다. 압축/축소 시 원본 보존 옵션의 정책 필요.
- 현재 완료·기록 삭제 기능은 존재하나 기기 삭제/저장소 퇴거로 소실될 수 있고 백업이 없다.
- 현재 서비스 워커는 앱 셸을 캐시하지만 **OCR CDN과 학습 모델의 완전 오프라인 가용성을 보장하지 않는다**.
- 현재 PWA는 잠금화면 시스템 카메라 대체, 차량 하차 자동 감지를 제공하지 않는다.

## 7. 서비스 핵심 여정(User Journey)

### J01. 첫 설치 없이 사용
1. 사용자가 URL/홈 화면 바로가기를 연다.
2. 홈은 현재 주차가 없으면 **가장 큰 행동 하나** `주차 위치 사진 찍기`를 보여준다.
3. 최소 설명: “기둥 번호를 찍으면 사진과 시각이 저장됩니다. 돌아올 때 바로 볼 수 있어요.”
4. 사진 촬영 시점에만 카메라 접근. 위치는 권한을 주지 않아도 사용 가능.
5. 촬영이 끝나면 로컬 저장 성공을 확인한 뒤 기록 카드를 노출한다.
6. 추가 설정/권한/OCR 검증은 필요한 순간에만 요청한다.

### J02. 낯선 주차장 → 빠른 기록
1. 사용자가 차에서 내려 구역 표지판 근처에서 잠금화면/홈/PWA 진입.
2. 카메라 화면이 열리고 주차 표기 촬영을 안내한다.
3. 사용자가 `B3 · C-27` 표지판을 촬영한다.
4. 시스템은 로컬 저장 트랜잭션이 성공한 경우에만 `기록 완료`를 표시한다.
5. 시스템은 비동기 OCR로 값을 **제안**하고, 값·원본 이미지를 카드에 보여준다.
6. 사용자는 원하면 출입구/엘리베이터 사진 또는 한 줄 메모를 추가한다.
7. 사용자는 앱을 닫아도 된다. 이때 저장되지 않은 추가 변경은 명확히 알린다.

### J03. 볼일 완료 → 차량 찾기
1. 사용자가 앱을 연다. **활성 기록이 있으면 무조건 현재 주차 카드가 첫 화면**.
2. 가장 큰 정보는 `층 · 구역 · 번호`, 그다음 `출입구/엘리베이터`와 `원본 사진`.
3. 사용자가 이동 중 사진을 확대해 확인할 수 있다.
4. 위치에 불확실성이 있으면 `사진에서 추정`/`직접 확인됨`을 구분한다.
5. 사용자가 차량을 찾으면 `차를 찾았어요`를 누르고 세션을 종료한다.
6. 세션이 완료 이력에 남는다. 종료하지 않아도 자동 제거하지 않는다.

### J04. 동승자에게 공유
1. 사용자가 활성 기록에서 `공유`를 선택한다.
2. 공유 미리보기에서 장소/층/구역/출입구/시각 중 보낼 항목을 확인한다.
3. 기본은 텍스트 형태. 사진·정밀 위치는 사용자가 별도 선택한다.
4. 공유받는 쪽은 앱 설치 없이 읽을 수 있어야 한다(미래의 공유 링크 기능 시).
5. 공유 취소·만료와 민감 정보 표기 정책을 제공한다(서버 링크 도입 시).

### J05. 이미 기본 카메라로 찍은 사진 활용
1. 사용자가 기존 카메라로 주차 표지를 촬영한다.
2. 사진첩 공유 메뉴/차여기 사진 가져오기로 진입한다.
3. 사진 저장 및 OCR 제안. 원본 촬영 EXIF 시간은 신뢰 가능한 앱 기록 시각과 구분한다.
4. 중복 사진/기록 여부를 확인하고 새 세션 또는 기존 세션에 첨부한다.
5. 복귀 시 차여기 기록을 이용한다. 이 경로는 카메라 사용 습관 변경에 실패해도 남는 대안이다.

### J06. P1 하차 추정 → 기록 유도
1. 사용자가 명시적으로 활동 인식/알림 설정을 켠다.
2. 지원 환경에서 차량 활동 종료 등 여러 신호로 하차를 **추정**한다.
3. 운전 중이거나 중복 알림 쿨다운 기간에는 알림을 제한한다.
4. `주차하셨나요? 사진으로 저장` 형태의 선택적 알림을 보여준다.
5. 탭 시 사진 기록으로 진입한다. `주차 안 했어요`/`앞으로 알림 줄이기`를 제공한다.
6. 시스템은 클릭했다고 주차를 완료한 것으로 계산하지 않는다.

### J07. 주차 사진 분실/오프라인/불명확
1. 사진 촬영 실패 시 재시도 또는 수동 입력.
2. OCR 실패 시 사진과 시간은 그대로 유지.
3. 기기 저장소 공간 부족 시 **저장 실패**를 명확히 표시하고 카메라로 돌아가는 등 복구 방법 제안.
4. 오프라인에서도 캐시된 앱 셸·기기 데이터 접근은 가능해야 하지만, 캐시 초기화/브라우저 정책에 따른 제약을 고지.
5. 서비스 데이터가 손실됐을 때 존재하지 않는 기록을 복구 가능하다고 약속하지 않는다.

│  ├─ 목록 / 상세 / 사진 / 재활성화 / 삭제
│  └─ (P2) 검색 / 내보내기
└─ 설정
   ├─ OCR 사용 여부 / 데이터 보관 안내

- 주차장 이름이 추정인 경우 명칭보다 확인된 위치 필드가 우선이다.

## 9. 기능별 상세 요구사항 및 인수 조건(Acceptance Criteria)

### FR-01. 앱 실행·첫 사용(P0)
**목적:** 설치 장벽 없이 필요한 순간 바로 사용.
- FR-01-01 `MUST`: 첫 실행은 회원가입·휴대폰 번호·로그인을 요구하지 않는다.
- FR-01-02 `MUST`: 활성 기록 없을 때 `사진으로 기록`이 최상위 CTA다.
- FR-01-03 `MUST`: 사용자가 사진 촬영/가져오기/수동 기록의 대안을 볼 수 있다.
- FR-01-04 `SHOULD`: 가벼운 설명만 제공하고 전체 튜토리얼을 강제하지 않는다.
- FR-01-05 `MUST`: 기록 보관 위치(기기), 기기 변경 시 비동기화 사실을 최초 사용 또는 설정에서 알린다.
- **AC-01:** 새 브라우저에서 URL→촬영 시작까지 계정 화면 0개; 활성 기록 유무에 따라 랜딩이 달라짐; 카메라 거부 시 가져오기/수동 기록 가능.

### FR-02. 사진 촬영·선택(P0)
- FR-02-01 `MUST`: 지원 기기에서 후면 카메라를 우선 제안하되, 브라우저에 따라 파일 선택기가 나올 수 있음을 고려한다.
- FR-02-02 `MUST`: 촬영 취소는 세션 미생성으로 종료(기존 세션 유지).
- FR-02-03 `MUST`: 카메라/파일 선택기 완료 후 화면을 유지하면서 저장 상태를 표시한다.
- FR-02-04 `SHOULD`: 카메라/사진 파일의 지원 포맷과 용량을 검사한다. HEIC/HEIF 등은 플랫폼별 테스트한다.
- FR-02-05 `SHOULD`: 흐린 사진이면 재촬영을 제안하되, 기록 자체를 막지 않는다.
- FR-02-06 `MUST`: 사진에는 사람·차량 번호판 등이 포함될 수 있으므로 공유 전 고지한다.
- **AC-02:** 사진 선택 취소 시 기존 활성 기록 변동 없음; 이미지가 저장되지 않았는데 ‘저장됨’ 메시지 금지; 지원되지 않는 포맷은 복구 문구 노출.

### FR-03. 즉시 저장·오프라인(P0)
- FR-03-01 `MUST`: 사진 저장은 OCR과 분리된 영속 트랜잭션이다.
- FR-03-02 `MUST`: 저장 성공 반환 후에만 기록 완료 표시.
- FR-03-03 `MUST`: `createdAt`은 기록 생성 기기 시각이며 실제 입차 시각과 혼동하지 않는다.
- FR-03-04 `MUST`: 저장 실패 시 사진이 보존됐는지 상태를 숨기지 않는다.
- FR-03-05 `SHOULD`: 저장소 사용량, 브라우저 데이터 삭제 위험 안내, 명시적 데이터 내보내기.
- FR-03-06 `SHOULD`: 중복 탭/중복 카메라 콜백으로 세션이 중복 생성되지 않게 멱등 키를 사용한다.
- **AC-03:** OCR 강제 실패와 네트워크 차단에서도 사진/시각 저장 성공; 저장 직후 새로고침 및 앱 재실행 시 기록 조회; quota 오류 시 성공 토스트 미노출.

### FR-04. OCR 제안·확인(P0→P1 개선)
- FR-04-01 `MUST`: 층·구역·번호를 **서로 다른 필드**로 저장한다.
- FR-04-02 `MUST`: 인식한 값은 `추정값`, 직접 확인/수정한 값은 `확인값`으로 구분한다.
- FR-04-03 `MUST`: 미인식은 빈값으로 남기며 유추해 확정하지 않는다.
- FR-04-04 `MUST`: 오류·타임아웃·오프라인 시 원본 사진과 세션 유지.
- FR-04-05 `SHOULD`: 한글·영어·숫자 혼합 표기를 지원한다. 모델 지원이 없는 언어는 미지원 표시.
- FR-04-06 `SHOULD`: OCR 결과 전체 텍스트·필드별 후보와 신뢰도·처리 버전을 진단용으로 보존하되 데이터 최소화 원칙 적용.
- FR-04-07 `MUST`: OCR이 뒤늦게 끝나도 사용자가 수정한 필드를 덮어쓰지 않는다.
- FR-04-08 `SHOULD`: `지하 3층`, `B-3`, `B3F` 등을 `B3`으로 정규화하되 원문 유지.
- FR-04-09 `SHOULD`: `C-27`, `C구역 27번`, `C동 27호` 등의 의미가 불명확할 때 필드 선택을 요구한다.
- **AC-04:** OCR 실패·부분 인식·충돌 입력·완료 후 도착한 결과·이상 텍스트 5종 이상 테스트; 사용자가 확인한 값은 자동 갱신되지 않음.

### FR-05. 주차 위치 편집(P0)
- FR-05-01 `MUST`: 장소·층·구역·기둥/번호·출입구·메모를 별도 수정 가능.
- FR-05-02 `MUST`: 공란 허용, 사진만 있는 세션도 정상.
- FR-05-03 `MUST`: 저장 완료 여부와 오류 표시.
- FR-05-04 `SHOULD`: `확인 완료` 표시를 사용자 직접 수정/확인한 필드에만 부여.
- FR-05-05 `SHOULD`: 변경 전후 값과 시각을 로컬로 추적해 OCR 수정률을 측정(선택적).
- **AC-05:** 입력 필드 라벨 명확, 저장 후 새로고침 유지, 화면 닫기/취소 시 미저장 상태 관리.

### FR-06. 활성 세션 관리(P0)
- FR-06-01 `MUST`: 기본 정책은 한 사용자/기기에서 **활성 세션 1개**.
- FR-06-02 `MUST`: 새 기록 시작 시 기존 활성 세션을 사용자가 알고 교체하도록 한다.
- FR-06-03 `MUST`: 기존 세션은 `완료 후 새 기록`, `기존 유지`, `취소` 중 하나로 선택.
- FR-06-04 `SHOULD`: 실수로 완료했다면 재활성화가 가능하되 다른 활성 기록 처리 정책을 적용.
- FR-06-05 `MUST`: 앱 백그라운드 진입이나 시간 경과만으로 세션을 임의 완료하지 않는다.
- FR-06-06 `MUST`: 샘플 세션은 실제 세션과 분석 지표에서 구분한다.
- **AC-06:** 활성 세션이 있는 상태에서 새 사진 촬영 시 기존 기록이 묻지 않고 사라지거나 자동 완료되지 않음(현재 코드 개선 필요).

### FR-07. 복귀 카드(P0)
- FR-07-01 `MUST`: 앱 재진입 시 활성 기록이 있으면 그 카드로 시작한다.
- FR-07-02 `MUST`: 가장 신뢰할 수 있는 정보를 상단에 표시한다. 사진만 있으면 사진 최우선.
- FR-07-03 `MUST`: 층·구역·번호를 큰 글씨로 표시하고, 출입구/엘리베이터 사진과 메모에 즉시 접근.
- FR-07-04 `MUST`: OCR 후보와 사용자 확인값의 표현 차이를 유지한다.
- FR-07-05 `MUST`: 시설지도/정확한 실내 위치가 없을 때 ‘도보 2분’ ‘오른쪽으로 10m’ 같은 가공된 경로·시간을 만들지 않는다.
- FR-07-06 `SHOULD`: 한 손 조작, 큰 버튼, 햇빛이 없는 환경의 대비 지원.
- **AC-07:** 온라인·오프라인 새로고침 후 2탭 이내 원본 사진 진입; OCR 없음/장소 없음에서도 화면 깨짐 없음.

### FR-08. 출입구/엘리베이터 단서(P0)
- FR-08-01 `MUST`: 출입구 표기/엘리베이터 번호를 자유 텍스트로 저장한다.
- FR-08-02 `MUST`: 주차 표지 사진과 별도 `출입구 사진`을 첨부 가능.
- FR-08-03 `SHOULD`: 출입구에 대한 입력은 **선택**이며 촬영 직후 흐름을 방해하지 않는다.
- FR-08-04 `COULD`: 시설별 출입구 명칭 표준화를 도입하되 공식 시설 정보 없이는 임의 통합하지 않는다.
- **AC-08:** 출입구 미입력에서도 복귀 가능; 첨부한 사진 확대·삭제·교체 가능.

### FR-09. 주차 경과 시간·알림(P0/P2)
- FR-09-01 `MUST`: 기록 생성 시각부터 경과 시간을 표시한다.
- FR-09-02 `MUST`: `기록 시각`과 실제 입차/주차요금 시작 시각을 명확히 구분.
- FR-09-03 `SHOULD P2`: 사용자가 `1시간 후 알림`처럼 직접 알림 시간을 지정할 수 있다.
- FR-09-04 `MUST P2`: 통신/OS 알림 제한으로 예약이 보장되지 않으면 조건을 고지한다.
- FR-09-05 `COULD P3`: 공식 요금/무료 주차 정책과 연계 시에만 요금 예측 제공.
- **AC-09:** 기기 시각 변경/시간대 변경/일광절약시간/장기 주차 테스트; 경과시간 오류는 분명하게 표시.

### FR-10. 공유(P0→P2)
- FR-10-01 `MUST`: 최소 텍스트 공유(장소가 있으면 표시, 층·구역·출입구·기록 시각).
- FR-10-02 `MUST`: Web Share API 미지원 시 복사/수동 복사를 제공.
- FR-10-03 `MUST`: 연락처 자동 접근을 하지 않는다.
- FR-10-04 `SHOULD`: 위치·사진 등 민감도가 높은 필드는 별도 선택.
- FR-10-05 `COULD P2`: 기간이 제한된 공유 링크, 접근 취소, 링크 비활성화 기능.
- **AC-10:** 공유 취소는 실패로 기록하지 않음; 정확하지 않은 OCR은 `추정` 표기하여 전달.

### FR-11. 이력·완료·삭제(P0)
- FR-11-01 `MUST`: 사용자가 `차를 찾았어요`를 누르면 완료 상태로 이동한다.
- FR-11-02 `MUST`: 완료 기록은 최근순으로 조회 가능하고 사진/정보 확인 가능.
- FR-11-03 `MUST`: 개별 삭제와 전체 삭제에 확인 절차를 둔다.
- FR-11-04 `MUST`: 데이터 삭제 이후 복구 불가능할 수 있음을 사전에 고지한다.
- FR-11-05 `SHOULD`: 기록 재활성화는 기존 활성 세션 충돌을 검증한다.
- FR-11-06 `COULD`: 오래된 기록 보존기간·자동 삭제는 명시적 사용자 선택으로만 활성화.
- **AC-11:** 완료·재활성화·개별 삭제·전체 삭제 이후 재시작 검증; 삭제 실패는 성공 표시 금지.

### FR-12. 빠른 진입(P1)
- FR-12-01 `MUST`: 지원 기기에서 홈 화면 바로가기를 안내한다.
- FR-12-02 `SHOULD`: iOS의 지원 버전에서는 **네이티브 앱 + LockedCameraCapture 확장** 가능성 검증.
- FR-12-03 `SHOULD`: Android에서 앱 바로가기/위젯/Quick Settings Tile 등 OS 허용 범위 탐색.
- FR-12-04 `SHOULD`: 기존 카메라 사진을 공유 메뉴에서 주차 기록으로 가져오기.
- FR-12-05 `MUST`: 사용자가 직접 OS 설정해야 하는 경로를 자동 완료됐다고 표시하지 않는다.
- **AC-12:** 잠금 상태에서 실행·해제/취소·권한 변경·기기 재부팅, 시스템 카메라 대비 조작 단계·시간 비교.

### FR-13. 하차 추정 및 알림(P1, 네이티브 검토)
- FR-13-01 `MUST`: 자동 감지는 **기능별 옵트인**이며 거절해도 기본 기록 가능.
- FR-13-02 `MUST`: 알림은 주차 **추정** 문구로만 발송. 사용자가 확인하기 전 주차 여부 확정 금지.
- FR-13-03 `SHOULD`: 활동 상태/연결 해제/시간·장소 등을 이용해 오탐 완화하되 보편적인 감지 기능을 약속하지 않는다.
- FR-13-04 `MUST`: 운전 중에는 카메라 촬영을 유도하지 않는다.
- FR-13-05 `MUST`: `주차 아님`, `나중에`, `알림 줄이기`, `끄기` 제공.
- FR-13-06 `SHOULD`: 장소별/시간별 알림 중복 제거, 일정 쿨다운, 사용자 맞춤 빈도.
- FR-13-07 `MUST`: 알림에서 바로 카메라를 실행할 수 없으면 지원 가능한 중간 화면으로 연결.
- **AC-13:** 승객/택시/버스/대중교통/휴게소 잠깐 정차·블루투스 끊김·멀티 디바이스 상황을 테스트. 자동 사진 촬영 금지.

### FR-14. 데이터 내보내기·동기화(P1/P2)
- FR-14-01 `SHOULD P1`: 사용자가 사진·메타데이터를 일반 파일로 내보낼 수 있다(예: ZIP+JSON).
- FR-14-02 `MUST P1`: 내보내기 파일에는 민감한 사진/이동 장소가 포함될 수 있음을 고지.
- FR-14-03 `MUST P2`: 기기 간 동기화는 별도 로그인/동의·보안 설계 후 도입.
- FR-14-04 `MUST P2`: 암호화 전송/저장·계정 삭제·백업 삭제·분쟁 시 복구 정책 수립.
- **AC-14:** 기기 변경/저장소 삭제 상황에서 백업·복원 및 파일 일치 검증; 지원하지 않는 경우 사용자에게 불가능함을 명시.

### FR-15. 시설 QR/지도/관리자(P3)
- FR-15-01 `MUST`: QR로 진입한 시설명·구역 정보는 시설 파트너 데이터 또는 사용자 확인값임을 표시.
- FR-15-02 `MUST`: 지도형 복귀 안내는 검증된 공식 시설 동선, 버전, 업데이트 날짜가 있을 때만 제공.
- FR-15-03 `SHOULD`: QR 설치 위치와 실제 사용 주차 구역의 관계를 시설별로 검증.
- FR-15-04 `MUST`: 시설 관리자 화면에는 개인 사용자의 사진·주차 이력을 기본적으로 노출하지 않는다.
- FR-15-05 `MUST`: 집계 지표는 익명화/최소화 기준 및 계약·개인정보 검토를 거친다.
- **AC-15:** QR 변조/잘못된 시설/도면 변경/동선 폐쇄/관리자 권한 오류 테스트.

## 10. 문자 인식(OCR) 및 추론 품질 설계

### 10.1 입력·처리 단계
```text
사진 수집 → 무결성 검사 → 로컬 저장 완료
→ (비동기) 이미지 회전/크롭 후보 → OCR 언어 모델
→ 텍스트 블록 감지 → 주차 표기 정규화 → 필드별 후보·신뢰도
→ UI에 제안 → 사용자 확인/수정 → 확인된 값만 확정
```

### 10.2 인식 규칙 예시
| 입력 원문 | 정규화 후보 | 주의 |
|---|---|---|
| `B3`, `B3F`, `B-3` | floor=`B3` | 건물/승강기 표기일 수도 있음 |
| `지하 3층`, `지하3F` | floor=`B3` | 표기 확인 필요 |
| `C27`, `C-27` | section=`C`, spot=`27` | 시설별 규칙 검증 필요 |
| `C 구역 27번` | section=`C`, spot=`27` | 단어 위치/문맥 이용 |
| `A동 15번 기둥` | section 또는 building=`A`, spot=`15` | ‘동’을 ‘구역’으로 단정 금지 |
| `P3` | floor=`P3` 후보 | 지하층 B3과 동일 취급 금지 |
| `6F B구역` | floor=`6F`, section=`B` | 6층은 지하 아님 |
| `엘리베이터 5호기` | entrance=`5호기` 후보 | 주차 위치 필드와 분리 |
| 인식 불가·흐림 | 모든 미인식 필드=`null` | 사진 보존, 입력 강요 금지 |

### 10.3 신뢰도 정책
- **필드별 출처:** `manual`, `ocr`, `facility`, `imported`, `unknown`.
- **필드별 검증 상태:** `unconfirmed`, `user_confirmed`, `user_corrected`, `official_facility`.
- **신뢰도 숫자:** OCR 엔진 값은 *문자 인식 확신도*이지 ‘차량 실제 위치 정확도’가 아니다.
- **충돌:** 기존 수동 입력이 있으면 OCR이 덮어쓰지 않는다.
- **동일 사진 재분석:** 사용자가 요청하면 원본으로 새 후보를 제안하되 확정값 유지.
- **모델 버전 관리:** 인식 엔진·버전·언어·규칙 버전을 진단 로그에 연결.
- **벤치마크:** 실제 국내 주차장 사진(조명·각도·한글·영문·반사·멀티 표지판)으로 라벨링하고 평가한다. 허가/촬영 동의 및 민감 정보 마스킹 방침 적용.

### 10.4 사용자에게 보여줄 문구
- 인식 성공: `사진에서 B3 · C구역 · 27번을 읽었어요. 맞는지 확인해 주세요.`
- 부분 성공: `B3은 읽었지만 구역·번호는 확인하지 못했어요.`
- 실패: `사진은 저장했어요. 위치 정보가 읽히지 않으면 사진을 보거나 직접 입력할 수 있어요.`
- 정정 후: `직접 확인한 위치로 저장했어요.`

## 11. 데이터 모델(Data Model)

### 11.1 핵심 엔터티
- `ParkingSession`: 하나의 주차부터 복귀 완료까지.
- `ParkingPhoto`: 위치/출입구/보조 사진과 원본 처리 정보.
- `ParkingField`: 층·구역·번호 등의 현재 값, 출처, 검증 상태.
- `OCRAnalysis`: 텍스트 원문, 필드 후보, 모델/처리 상태.
- `DetectionSignal`(P1): 하차 추정 신호와 알림 노출 여부; 기본 설정에서 최소한의 로컬 보관.
- `Reminder`(P2): 사용자 설정 주차 시간 알림.
- `Facility`(P3): 검증된 장소·시설 구조·유효 일자.
- `ShareGrant`(P2): 접근 기간/폐기 가능한 공유 범위.
- `ConsentRecord`(P1+): 개별 권한·동의 버전·철회 시각.

### 11.5 데이터 보존 및 삭제 정책
- **P0:** 사용자가 삭제할 때 로컬 기록 삭제. 기기/브라우저 데이터 삭제 또는 저장소 정책으로 기록이 손실될 수 있다.
- **P1:** 사용자가 내보내기·백업을 직접 선택할 수 있도록 한다.
- **P2 서버 사용:** 개인정보 처리방침에 보관 기간·동의 목적·삭제 시점·제3자 제공·국외 이전 등을 명시하고 별도 확정.
- 기록 사진에는 얼굴·차량 번호판·방문 장소가 포함될 수 있다. 서버/분석 전송을 기본값으로 하지 않는다.
- OCR에서 추출된 전체 원문은 오류 분석 목적이 끝나면 최소화·제거 방침을 검토한다.

## 12. 세션 상태 기계 및 예외 정책

### 12.1 상태도
```text
NO_SESSION
  ├─ 촬영 취소 → NO_SESSION
  └─ 사진 영속 저장 성공 / 수동 기록 생성 → ACTIVE
ACTIVE
  ├─ 필드/사진 수정 → ACTIVE
  ├─ 새 기록 요청 → 사용자 확인 → COMPLETED + NEW_ACTIVE
  ├─ 새 기록 취소 → ACTIVE 유지
  ├─ 차량 찾음(사용자 확인) → COMPLETED
  └─ 개별 삭제 확인 → DELETED
COMPLETED
  ├─ 조회/공유 → COMPLETED
  ├─ 재활성화(다른 활성 세션 확인) → ACTIVE
  └─ 삭제 확인 → DELETED
```

### 12.2 불변 조건(Invariants)
- 저장 성공을 선언한 기록은 새로고침 후 복원 가능해야 한다(브라우저 저장소 정리 전제 제외).
- 활성 세션 수는 0 또는 1개이며, 전환 시 이전 세션을 사용자에게 알린다.
- OCR 처리 성공/실패가 세션 `ACTIVE/COMPLETED` 상태를 임의 변경하지 않는다.
- `user_confirmed` 필드는 자동 인식/수입/시설 업데이트로 덮어쓰지 않는다.
- 완료 후 늦게 도착한 OCR 결과가 기록을 잘못 바꾸지 않는다.
- 사진이 삭제되면 연관 OCR 민감 원문/파생 데이터도 삭제 정책을 따른다.
- 복귀 동선이 없는 시설에서는 ‘정밀 길 안내’를 노출하지 않는다.

### 12.3 예외 매트릭스
| 조건 | 사용자에게 보이는 결과 | 데이터 처리 | 운영/QA |
|---|---|---|---|
| 카메라 권한 거절 | 수동 기록/사진 가져오기 제안 | 기존 세션 유지 | 권한 복구 시나리오 |
| 파일 선택 취소 | 기존 화면 유지 | 신규 세션 없음 | 중복 생성 방지 |
| OCR 모델 다운로드 실패 | 사진 저장, `인식 못 함` | 로컬 사진 유지 | CDN/오프라인 테스트 |
| OCR 오인식 | `추정` 라벨, 수정 | 수동 확인 우선 | 필드별 정확도 측정 |
| IndexedDB quota 초과 | `저장 실패`, 공간 확보/다시 시도 | 성공 처리 금지 | 대용량 사진 테스트 |
| 브라우저 저장소 삭제 | 기록 없음·보관 제약 고지 | 복구 미지원 | 백업 요구 검토 |
| 신규 기록 중 이전 활성 존재 | 기존 기록 처리 선택 | 묵시적 완료 금지 | 트랜잭션 원자성 |
| 두 번 빠르게 촬영 | 저장 상태 표시/중복 방지 | 1세션 또는 명시 추가 | 레이스 컨디션 |
| GPS 없음 | 위치 추정 없이 사용 | 장소 null | 권한 미허용 테스트 |
| 지하에서 네트워크 끊김 | 로컬 화면/데이터 사용 | OCR CDN 불가 가능 | 최초 캐시 여부 구분 |
| 주차하지 않은 알림 | `주차 아니에요`, 빈도 줄이기 | 오탐 기록 최소화 | 승객·택시 테스트 |
| OS 절전·알림 차단 | 직접 기록 가능 | 자동화 의존 없음 | 기기 매트릭스 |
| 공유 취소 | 취소 후 원위치 | 기록 불변 | 오류와 취소 구분 |
| 기기 시간 불일치 | `기기에 기록된 시각` 표기 | timeOrigin 유지 | 시계 변경 테스트 |

## 13. 기술 아키텍처 및 개발 전략

### 13.1 단계별 구조
**P0 현재 웹/PWA**
```text
Mobile Safari / Chrome
  ├─ UI: HTML + CSS + JavaScript
  ├─ Camera: file input (capture=environment 요청)
  ├─ Storage: IndexedDB (세션·사진 Blob)
  ├─ OCR: 브라우저 Tesseract.js / CDN 모델(연결 필요)
  ├─ Share: Web Share API 또는 텍스트 복사
  ├─ Offline Shell: Service Worker / Cache API
  └─ Hosting: GitHub Pages HTTPS (정적 배포)
```

**P1 네이티브 경험 검증**
```text
iOS App / Android App
  ├─ Locked/Quick Entry (OS별 기능)
  ├─ Camera Native Capture
  ├─ On-device OCR (Vision / ML Kit 등)
  ├─ Local DB + photo storage
  ├─ Optional Activity/Car signal and notification
  ├─ Share Extension / Shortcut / Widget
  └─ P0 데이터 가져오기 설계(필요 시)
```

**P2/P3 선택적 백엔드**
```text
Mobile Client --TLS--> Auth / Account Service (opt-in)
              ├── Encrypted Storage / Sync
              ├── Consent & Audit
              ├── Optional Time-Limited Share Service
              └── (P3) Verified Facility Catalog / B2B API
```

### 13.2 구현 의사결정
- **웹 유지 이유:** 저비용 배포, 가입 없이 가설 검증, 주차장 QR 진입 가능.
- **네이티브 검토 이유:** iPhone 잠금화면 전용 카메라, Android 활동 인식, OS 공유 확장 등 웹이 제공하지 못하는 진입 경로.
- **처음부터 서버를 두지 않는 이유:** 개인정보·비용·복잡성 감소. 단, 백업 및 정확한 리텐션 측정에 한계.
- **추론 전략:** 기기 내 OCR 우선. 클라우드 OCR은 별도 동의와 명확한 추가 정확도 이점이 있을 때 검토.
- **GPS 전략:** 선택적 시설명 제안에만 사용. 지하 층/구역 결정에 사용 금지.
- **OS 제약:** 지원되는 모든 iPhone에서 동일한 자동화가 작동한다고 가정하지 않으며 디바이스/OS 테스트로 검증.

## 15. 사용자 분석·이벤트·실험 계측

### 15.1 P0 분석 방식
개인정보 수집이 필요하지 않은 앱 개선 원칙을 유지한다. **초기 웹 MVP는 서버 기반 이벤트 수집이 구현되어 있지 않다.** 현장 테스트에서는 실험 참가자의 별도 동의로 관찰 기록·시계 측정·설문·선택적 진단 데이터 내보내기를 활용한다. 추후 도입하는 분석 SDK는 민감 정보/원본 이미지를 자동 수집하지 않도록 한다.

### 15.2 이벤트 사전
| Event | 발생 시점 | 주요 속성(예) | 금지/주의 |

| `app_opened` | 앱 진입 | source, has_active | 사진/정밀 주소 제외 |

### 15.3 실험 설계
- **실험 1 (가치 검증):** 카메라+사진첩 vs 차여기 직접 실행, 동일·유사한 주차 상황에서 `기록 시간`, `단서 확인 시간`, `복귀 도움` 비교. 참가자별 역순 배치로 학습효과 완화.
- **실험 2 (습관):** 사용자별 2회 이상의 ‘기록 필요 주차’ 상황에서 자발적 선택 관찰. 강제 과제를 반복 사용으로 계산 금지.
- **실험 3 (출입구):** `위치 표기만` vs `출입구 단서도 기록` 비교. 실제 복귀 동선·실패 횟수 기록.
- **실험 4 (자동 감지):** P1 네이티브 기능을 동의한 참가자에 한해 감지 알림 vs 빠른 실행만 제공. 승객·택시·도보 등 오탐 표본 포함.
- **실험 5 (비용/가치):** 반복 사용자가 실제로 원하는 데이터 기능(시간 알림/공유/이력)을 선택하게 한다. 말로만 ‘원한다’는 응답과 실제 활성화를 분리.

### 15.4 표본과 관찰 도구
- 1차: 20~30명, 시설 3종 이상(쇼핑몰·병원·복합시설), iPhone/Android 분리.
- 측정: 진입/촬영/저장/단서 확인의 스톱워치+스크린 기록(명시적 동의), 현장 메모, 설문.
- 오류 분류: 기록 누락/인식 오류/잘못된 출입구/오탐/저장 실패/사용자 포기.
- 유용성 인터뷰 예: “다시 촬영해야 한다면 무엇을 바꾸겠어요?”, “그때 왜 기본 카메라 대신 이것을 선택했나요?”, “차를 찾을 때 실제 어떤 정보를 먼저 확인했나요?”
- 배제 기준: 테스트 수행을 강제해 자발적 행동 측정이 불가능한 경우, 차량 복귀를 할 수 없는 조건, 안전하지 않은 주차 상황.

### 15.5 결과 판정·중단 기준
- 저장 실패가 반복되면 습관 실험보다 **데이터 신뢰성 개선**을 우선한다.
- 재사용률이 기준에 못 미치지만 복귀 효용이 높다면 **카메라 공유 확장/시설 QR** 실험으로 전환한다.
- 복귀 효용도 낮으면 제품 차별화가 불충분하므로 B2C 앱 확대를 중단한다.
- 오탐이 높으면 자동 감지 범위를 축소하거나 삭제한다. ‘알림을 많이 보내면 기록이 늘어난다’는 단기 착시는 허용하지 않는다.
- B2B 도입은 파일럿 계약/구매 의사가 확인되기 전까지 별도 전용 기능을 대규모 개발하지 않는다.

## 16. 접근성(Accessibility)·국제화·UX 카피

### 16.1 접근성 요구사항
- WCAG 2.2 AA 지향: 색상에만 의존하지 않는 상태 표시, 고대비, 스크린리더 레이블/헤딩, 포커스 복귀.
- 터치 대상 크기와 간격을 모바일에서 충분히 확보; 손가락 하나로 주요 CTA 실행.
- 이미지·원본 사진에는 기록의 역할을 설명하는 대체 텍스트 제공(원본 사진 내용 전체를 자동 사실로 묘사하지 않음).
- 사진 확대 모달에서 확대·닫기·초점 관리·스크롤 배경 잠금.
- 텍스트 크기 확대·글자 잘림·가로 화면·작은 화면 대응.
- 불안/서두르는 환경을 고려해 오류 메시지는 원인+할 수 있는 다음 행동을 제시한다.

### 16.2 언어/지역화
- 초기 한국어 우선. 주차 표기 OCR은 한국어·영문·숫자 혼합.
- UI 영어·일본어 확대는 실제 수요 검증 후. 장소/표기를 번역하면서 원문을 잃지 않는다.
- `B3`, `P2`, `3F`, `지하3층`은 시설별 의미가 달라 원문을 보관하고 정규화를 명시.
- 표시 날짜·시각은 현지 사용자 시간대로, 저장은 ISO UTC 기준.

## 17. 비기능 요구사항(NFR)·운영 기준

### 17.1 성능/안정성
- 주요 성능은 네트워크와 무관한 **로컬 사진 저장**을 우선 최적화.
- 이미지 처리 중 브라우저 메모리 부족/앱 강제 종료에 대비해 원본 저장과 분석을 분리.
- IndexedDB 실패 및 불안정한 사파리 프라이빗 모드에 대한 대체 UX.
- 서비스 워커 캐시가 이전 버전의 JS/HTML을 고정해 오류를 내지 않도록 버전 무효화/업데이트 안내.
- CDN 장애 시 기본 기록은 동작; OCR만 실패 처리.
- 사진 용량 추정과 보관 위험 안내. 원본 압축 여부는 품질/증빙 가치와 저장 비용의 균형으로 결정.

### 17.2 관측성·로그
- P0: 브라우저 개발자 콘솔 오류와 로컬 테스트 체크리스트. 사용자 사진/기기 위치를 로그에 출력하지 않음.

## 20. 수익모델·사업성 검증(제품과 분리하여 판단)

### 20.1 B2C 기본 방향
- 초기는 **무료**로 제공. 반복 사용이 확인되기 전 구독/광고를 강제하지 않는다.
- 유료 후보(미검증): 안전한 암호화 백업, 가족 공유, 고급 리마인더, 다기기 기록.
- 약점: 카메라의 무료 대체력, 사용 빈도 낮음, 인앱 결제 수요 불명확.
- 사용자가 실제 돈을 지불할 의사가 있는지 **가격 제시 실험**으로 검증한다. 설문 ‘지불 의향 있음’만으로 제품 매출을 예측하지 않는다.

### 20.2 B2B 후보

## 22. 의사결정 게이트(Go / Iterate / Pivot / Stop)

### Gate A — P0 기록 신뢰성
- **GO:** 저장 성공, 재시작 후 복구, 복귀 카드, 명확한 실패 UX가 안정적.
- **ITERATE:** OCR 부정확하지만 사진 보관 안정적이면 인식보다 복귀 UX 개선.
- **STOP FOR FIX:** 실제 저장 실패가 성공으로 노출되거나 반복적인 기록 소실.

### Gate B — 기본 카메라 대비 효용
- **GO:** 촬영 시작/복귀 탐색 중 적어도 한 지점에서 의미 있는 시간 절약, 사용자 체감 가치 확인.
- **PIVOT:** 기록 앱은 안 열지만 공유 가져오기/시설 QR은 사용 → 유틸리티/시설 진입으로 전환.
- **STOP:** 복귀 경험도 개선되지 않고 재사용 의지도 없음.

### Gate C — 습관과 진입
- **GO:** 유효 EPO에서 자발적 선택률 개선 및 알림 피로 허용.
- **PIVOT:** 자동 감지는 오탐이 높고 잠금화면만 유효 → 빠른 실행 중심.
- **STOP AUTO:** 감지 신호보다 오탐/삭제/권한 거절로 신뢰가 하락.

### Gate D — 사업화
- **GO:** 실제 지급 의향을 가진 B2C 사용자 또는 유료 시설 파일럿 계약 확인.
- **PIVOT:** 무료 도구로서는 유용하지만 독립 수익성이 낮음 → 화이트라벨/파트너 채널.
- **STOP COMMERCIAL:** 배포·지원·영업비용 대비 구매·유지 지표 부족.

## 24. 사용자 인터뷰 질문지 / 현장 테스트 스크립트

### 24.1 사전 행동 인터뷰(경험·행동 중심)
1. 최근 실제로 주차 위치를 잊어버렸던 순간을 구체적으로 설명해 주세요.
2. 어떤 시설이었고, 복귀할 때 무엇을 기억하지 못했나요(층/구역/동/출입구)?
3. 당시 사진을 찍었나요? 찍지 않았다면 왜 그랬나요?
4. 사진을 찍었다면 돌아갈 때 사진을 찾는 데 얼마나 걸렸나요?
5. 예전에 시도했다가 다시 쓰지 않은 주차 기록 도구가 있나요? 왜 그만뒀나요?
6. 주차 직후에 가장 먼저 하는 행동은 무엇인가요?
7. 알림이 주차 직후 뜬다면 언제 유용하고 언제 불편할까요?
8. 동승자에게 주차 위치를 공유한 경험이 있나요? 어떤 정보를 보냈나요?
9. 사진 외에 정말 기억해두고 싶은 정보가 있나요?
10. 다음 번 비슷한 상황에서 차여기를 *스스로* 열 이유가 있나요? 없으면 무엇이 부족한가요?

### 24.2 과업 테스트
- **T1:** 낯선 지하주차장에 도착. 평소 방식으로 기록하고 활동.
- **T2:** 다른 주차 상황에서 차여기 방식으로 기록(순서 반전 배치 가능).
- **T3:** 약 30분 이상 뒤 차량으로 복귀, 저장한 단서 사용.
- **T4:** 출입구 정보가 없어도 가능한지, 추가 기록이 유용했는지 확인.
- **T5:** 2회차 이상 주차에서 별도 요청 없이 어떤 앱을 먼저 실행하는지 관찰.

## 26. 출시 체크리스트(Release Gate)

### P0 일반 공개 전
- [ ] 개인정보/저장 안내가 앱에서 쉽게 확인된다.
- [ ] iPhone Safari·Android Chrome에서 촬영/가져오기/수동 기록이 동작한다.
- [ ] 로컬 저장 성공 시에만 성공 표시한다.
- [ ] 새로고침·앱 재실행 후 활성 기록과 사진이 남아 있다.
- [ ] OCR 장애 시 사진·세션을 잃지 않는다.
- [ ] 불명확 OCR 결과가 사실처럼 표기되지 않는다.
- [ ] 새 기록과 기존 기록 충돌이 명시적으로 처리된다.
- [ ] 데이터 삭제·과거 기록·사진 확대가 동작한다.
- [ ] 저장 공간 부족·기기 데이터 삭제 위험을 고지한다.
- [ ] 앱 셸 오프라인 표시와 OCR 오프라인 한계가 구분된다.
- [ ] 접근성·터치·폰트 확대에 치명적 장애가 없다.
- [ ] 최소 1개씩 실제 현장 주차·복귀 테스트를 완료한다.
- [ ] GitHub Pages 배포 성공 및 모바일 URL 직접 스모크 테스트.

### P1 기능 공개 전
- [ ] 지원 OS·기기·권한 조건이 실제 문서와 일치한다.
- [ ] 자동 감지는 사용자 동의를 받고 중지/삭제 가능하다.
- [ ] 승객·택시·잠깐 정차 등 오탐이 측정된다.
- [ ] 잠금화면 실행 시 개인 사진이 잠금 상태에서 부당 노출되지 않는다.
- [ ] 기본 카메라 대비 자발적 선택의 개선이 확인된다.

### P3 시설 파일럿 전
- [ ] 시설 공식 주차·동선 데이터 계약/업데이트 책임 정의.
- [ ] QR 악용·권한 분리·개인정보/장소 데이터 경계 확인.
- [ ] 구매자/예산/유료 파일럿 계약 조건 확인.
- [ ] 비용·운영 문의·성공 지표를 계약 기준으로 합의.
